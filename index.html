LOG 03 / 08

Key Waypoints (Core Concepts)

Our navigation systems locked onto four critical architectural patterns to ground our LLMs:

Retrieval-Augmented Generation (RAG)

Retrieves relevant information from an external knowledge base and supplies it to an LLM as context. Grounds AI in factual, proprietary data, reducing hallucinations.

Context Engineering

The discipline of deliberately curating exactly what an LLM sees in its finite context window. Prevents "context rot" and ensures AI remains focused and cost-efficient.

Text Embeddings

High-dimensional vectors representing semantic meaning. Maps language into a spatial continuum, allowing semantic search that matches intent over exact keywords.

Agentic RAG

LLMs act as orchestrators, utilizing a "Thought-Action-Observation" loop to dynamically route queries, call external tools, and decide if more retrieval is needed.

LOG 04 / 08

Deep Dive Discoveries

TECHNICAL PIPELINES EVALUATIONS

Chunking Strategies

To prevent "vector mush," we split data into sharp chunks: Fixed-Size (fast), Semantic (shifts at natural boundaries), Structural (by Markdown/JSON), and Late Chunking (embedding entire documents first).

Advanced Retrieval & Reranking

Fusing methods is critical. Hybrid Search combines Dense (semantic vectors) with Sparse (BM25 keyword) search, merged via Reciprocal Rank Fusion (RRF). We further refine results using highly precise Cross-Encoder Reranking.

GraphRAG & Relational Data

For multi-hop reasoning, we construct LLM-derived knowledge graphs. Extracting entities and relationships into graph DBs (like Neo4j) allows us to traverse edges via Cypher queries to answer holistic, global questions.

RAG and Vision Evaluations

We synthesize "Golden Datasets" and use LLM-as-a-Judge (e.g., GPT-4) to score Groundedness and Relevance. For Vision models, we apply rigorous graded rubrics checking layout hierarchy and text rendering accuracy.

LOG 03 / 08

Core Agent Architecture (Core Concepts)

Our fleet navigation systems locked onto four primary cognitive patterns for structuring agent reasoning:

ReAct Loop

Synergizes Reasoning (thought chain) and Acting (action plan generation) in an interleaved loop. Enables the agent to track plans, handle exceptions, and dynamically request tools.

Planner-Executor

Divides labor by using a larger, expensive model to generate an overarching plan upfront, and smaller, cheaper models to execute each individual step.

Supervisor Pattern

A centralized multi-agent system where a coordinator breaks down tasks, delegates them to specialized workers (researchers, coders), and synthesizes results.

Reflection Loop

A "draft, critique, revise" workflow where one generator model produces an output and another reflector model critiques it until it passes quality checks.

THE HARNESS EQUATION

Agent = Model + Harness. The harness provides the runtime loop, tools, and sandboxed execution environment. It acts as a cybernetic governor utilizing Guides (feedforward controls before acting) and Sensors (feedback controls to self-correct after acting).

LOG 04 / 08

Tools & Connectivity Deep Dive

INTEGRATION PROTOCOLS CONNECTIVITY BUS

Model Context Protocol (MCP)

Known as the "USB-C port for AI." An open-source protocol that acts as a standardized vertical bus connecting hosts (AI apps) to servers (data sources, tools, and prompts) without requiring custom API clients for every new integration.

Agent-to-Agent (A2A) Protocol

A horizontal communication protocol allowing autonomous, opaque agent applications built on different frameworks to discover, delegate, and collaborate securely without exposing their internal states or proprietary logic.

Client Tools vs Server Tools

Client tools run locally inside your app's code infrastructure, demanding manual tool execution. Server tools execute directly on the model provider's servers (e.g., Anthropic's sandboxed python shell or web search integrations).

LOG 03 / 08

Core Calibration Constants (Core Concepts)

Our telemetry dashboards rely on five primary mathematical foundations to evaluate agent correctness:

Accuracy

Right / Total

Out of all cases, how many were correct. Easy to explain, but weak for rare positive cases.

Precision

True Positives / Predicted Positives

When the model predicts positive, how often is it right? Use when false alarms are expensive.

Recall

True Positives / Actual Positives

Of all real positive cases, how many did the model catch? Use when missing a case is expensive.

F1 Score

2 × P × R / (P + R)

A single score that balances precision and recall. Useful when you care about both false alarms and misses.

Pass Rate

Passed / Total

How often an output clears a deterministic grader. Great for JSON validity, syntax tests, and tool call schemas.

METRIC RULE

Pick metrics by failure cost. If bad positives are dangerous, optimize precision. If missed positives are dangerous, optimize recall. If both matter, report F1 plus the raw counts.

LOG 04 / 08

Deep Dive Discoveries

EVALUATION METRIC FAMILIES DIAGNOSTIC RUBLICS

1. Classification & Retrieval

Evaluating search and structured prediction. Includes Exact Match (identity matching), Macro F1 (equal weight per class), Micro F1 (volume performance), Balanced Accuracy (handles imbalanced classes), and ranking metrics like NDCG, MRR, and MAP to reward relevant context appearing at the top of retrieval pipelines.

2. Natural Language Generation & Similarity

Assessing semantic quality. Employs n-gram overlaps like BLEU (translation) and ROUGE (summarization recall), alongside embedding tools like BERTScore. For subjective features, LLM-as-a-Judge uses structured rubrics to score Relevance, Coherence, Conciseness, Tone/Style, and Instruction Following.

⚠️ JUDGE CAUTION: LLM judges are flexible but can suffer from length, position, style, and self-preference bias. Use clear rubrics, blind pairwise comparisons, and human agreement checks.

3. RAG Grounding & Task Success

Validating facts and outputs. Uses Faithfulness (verifying claims in context), Response Relevancy, Context Precision (avoiding noise), and Context Recall. For autonomous agents, we track **Tool-Call Accuracy**, **Code pass@k**, **SQL Execution Accuracy**, and **Task Completion Rate**.

4. Risk, Reliability & Ops

Production safety and health. Tracks **Toxicity**, **Jailbreak Success Rate**, and **PII Leakage** alongside classic Ops parameters like **Latency** (p95), **Cost per successful task**, **Containment / Deflection** (resolution without human handoff), **Retry / Repair Rate**, and **Drift** over time.
